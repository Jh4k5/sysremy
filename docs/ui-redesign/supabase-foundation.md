# أساس Supabase 5.2 — بوابة إلزامية + ملف لكل مستخدم + مزامنة أوفلاين-أولاً

## المعمارية (مبنية ومُختبرة — محدّث 2026-10-26)

```
زائر ──► بوابة الدخول الإلزامية (auth-gate.tsx)
          │ لا تطبيق إطلاقاً قبل جلسة صالحة — بريد/كلمة أو Google
          ▼
     جلسة Supabase (uid)
          │ 1) setActiveUser(uid) → قاعدة Dexie مستقلة: SystemyDB-u-{uid}
          │ 2) activateSync(uid)  → محرك المزامنة
          ▼
     التطبيق كاملاً على قاعدة مستخدمه (كل الاشتراكات تنشأ بعدها)
          │
          ├─ كتابة محلية ──► خطافات Dexie تختم syncMs وتسجّل في syncOutbox
          │                   (حذف = شاهد قبر، والأوفلاين يعمل طبيعياً)
          ├─ متصل؟ ──► دفع دفعات (RPC sync_push بمنطق LWW) + سحب تدريجي
          │            (records?updated_at>=مؤشر) وتطبيق محلي بـ LWW
          └─ انقطع؟ ──► الشارة «محلي»؛ عند العودة: دورة فورية تلحق كل شيء
```

- **العزل**: كل مستخدم قاعدة IndexedDB باسمه (`SystemyDB-u-{uid}`) + RLS على
  السحابة (`auth.uid() = user_id`) — لا يرى أحدٌ بيانات غيره محلياً ولا سحابياً.
- **الدقة**: كل كتابة تختم `syncMs` (إيبوك مللي) — الصراع بين جهازين يحسمه
  «آخر كتابة تفوز» (LWW) على الخادم والعميل معاً؛ الحذف ينتشر بشواهد القبور.
- **المحفزات**: كتابة محلية (تراجع 1.5ث) · عودة الاتصال (نبضة health فورية) ·
  كل 60ث · رجوع التبويب · زر «زامن الآن» اليدوي.
- **كشف الاتصال**: أحداث المتصفح + نبضة فعلية إلى `/auth/v1/health` كل 20ث —
  لأن navigator.onLine يكذب خلف البروكسيات.

## الحالة الحية (تحقق مباشر ضد الخادم — 2026-10-26)

- ✅ **Google OAuth مهيّأ فعلياً**: `authorize` يرد 302 إلى
  `accounts.google.com/o/oauth2/v2/auth?client_id=671470048964-…` بمفاتيح
  حقيقية. سلسلة الزر مُوثّقة بشبكة المتصفح: التطبيق → authorize
  (`redirect_to` أصل الصفحة) → جوجل.
- ✅ **Redirect URLs مفتوحة**: أي `redirect_to` يُقبل (اجتاز فحص نطاق وهمي) —
  عودة OAuth تعمل من أي نطاق معاينة.
- ✅ **الدخول بالبريد**: كلمة خاطئة → رسالة عربية صادقة؛ حساب غير مؤكد →
  رسالة «بريدك ما تأكّد بعد…». التسجيل يرسل بريد التأكيد فعلاً
  (mailer_autoconfirm=false — التأكيد إلزامي بقرار المشروع).
- ❌ **هجرة SQL لم تُشغَّل بعد** — `profiles` و`records` و`sync_push` غير
  موجودة (PGRST205/PGRST202). التطبيق يعمل كاملاً محلياً بشارة
  «مزامنة معطّلة» الصادقة، وبطاقة الحساب تعرض **زر «انسخ أوامر التهيئة
  (SQL)»** — نسخة واحدة، لصق في SQL Editor، وبعد دقيقة تنقلب «متزامن»
  تلقائياً (إعادة تحقق دورية كل 60ث).

## ما هو مُختبر فعلياً (بالمتصفح، 390×844 RTL + 1280 سطح مكتب)

- ✅ **البوابة تحجب كل شيء**: زائر جديد يرى شاشة الدخول فقط — لا إعداد أولي،
  لا شاشات، لا قاعدة بيانات تُنشأ أصلاً قبل الدخول.
- ✅ **سلسلة Google كاملة**: نقر الزر → `authorize?provider=google&redirect_to=<الأصل>`
  → 302 → صفحة جوجل بالمفتاح الحقيقي (سجل شبكة حي). إكمال اختيار الحساب
  يحتاج جهاز المستخدم (لا يمكن محاكاته)، والعودة تلتقطها `detectSessionInUrl`.
- ✅ **داخل إطار المعاينة**: الزر يفتح تبويباً جديداً بدل التنقل داخل الإطار
  (جوجل يرفض الإطارات) — مع إرشاد صادق إن حجب المتصفح النوافذ.
- ✅ **ملف لكل مستخدم**: بعد الدخول تُنشأ `SystemyDB-u-{uid}` خاصة؛ الخروج
  يحفظها ويعيد البوابة، والعودة تدخل مباشرة ببيانات صاحبها.
- ✅ **الأوفلاين الكامل**: قطع الاتصال → «محلي — تعمل طبيعياً وتلحق عند
  العودة» → كتابة محلية ناجحة → عودة الاتصال → دورة فورية (مُثبت أيضاً
  بفشل شبكة حقيقي مصطنع أثناء الاختبار: صنّفه المحرك «محلي» بصدق).
- ✅ **حالة «تحتاج تهيئة» بالضبط كما ستظهر للمستخدم**: خادم محاكاة يرد بنفس
  أخطاء PGRST الحرفية للخادم الحقيقي → الشارة «مزامنة معطّلة» + بطاقة
  الحساب بصف التهيئة + الزر ينسخ الهجرة فعلياً (جلب 200 + حافظة + توست
  إرشادي بالإجراء التالي).
- ✅ **الصادر يلتقط كل شيء**: بعد الإعداد الأولي دُفعت الأنظمة الـ16 كاملة
  بأختام syncMs في دفعة واحدة؛ الحذف الجماعي يسجّل قبوراً فينتشر.
- ✅ وضع standalone (APK) يحترم البوابة نفسها. صفر أخطاء console/page.
- ✅ التذييل: يلتصق بأسفل الشاشة عند قصر المحتوى، ويُدفع طبيعياً بلا تغطية
  عند طوله (تحقق DOM هندسي على 1280×800 و1280×1100).

## الخطوة الوحيدة المتبقية عليك (لا تحتاج أي كود)

**تشغيل هجرة SQL — لتشغيل المزامنة**: من داخل التطبيق: شاشة «أنا» → بطاقة
الحساب السحابي → **«انسخ أوامر التهيئة (SQL)»** → Supabase → SQL Editor →
New query → الصق → Run. (أو انسخ `docs/ui-redesign/sync-migration.sql`
من المستودع — نفس المحتوى؛ المصدر واحد يُقدَّم من `/api/sync/migration-sql`.)

تنشئ الهجرة: `profiles` + `records` + `sync_push` (LWW محصّن ضد تصادم
المستخدمين) + RLS + **منح صريحة** (authenticated يقرأ/يكتب، anon محجوب) +
تريغر الملف الشخصي. إعادة التنفيذ آمنة. بعد دقائق تنقلب الشارة «متزامن»
تلقائياً — بلا أي تغيير في الكود.

لتجربة دخول البريد كاملة: أكّد بريداً واحداً من Authentication → Users →
Confirm (أو افتح رابط التأكيد من صندوق البريد).

## حدود معروفة (موثقة بلا تجميل)

- دفع/سحب الشبكة الحقيقي ضد `records` لم يُختبر بعد لأن الجدول لم يُنشأ —
  منطق LWW/القبور/المؤشر مُختبر محلياً وبمحاكاة مطابقة حرفياً لردود الخادم.
- LWW بحسابات ساعات الأجهزة: من يكتب أخيراً يفوز؛ ساعة جهاز خاطئة بفارق
  كبير قد تطغى كتابتها — سلوك قياسي لأنظمة local-first، مقبول لاستخدام فردي.
- رابط استعادة كلمة المرور يصل عبر البريد ويفتح نموذج كلمة مرور جديدة داخل
  التطبيق (PASSWORD_RECOVERY مُعالج) — تأكد أن نطاق المعاينة ضمن Site URL
  أو Redirect URLs إن لم يصل الرابط.
- حدود بريد Supabase المدمجة ضيقة (2-3 رسائل/ساعة) — للإنتاج اضبط SMTP.
- تحذير GoTrue «Multiple client instances» يظهر أحياناً في وضع dev بعد
  إعادة التحميل — ضجيج تطويري بلا أثر وظيفي (لا يظهر في بناء الإنتاج).
